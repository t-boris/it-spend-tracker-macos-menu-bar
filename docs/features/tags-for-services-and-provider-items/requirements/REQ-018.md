## Statement

Tag assignments shall be stored independently of refreshed provider data and identified by tracked service, target type and a stable reference, so they survive refreshes, restarts and month changes without being shared between different targets.

## Acceptance Criteria

- [x] Assignments persist across restarts, refreshes and month changes.
- [x] Identity includes the tracked service and the target type: a key by its provider ID; a breakdown item by dimension plus exact label, excluding the month; a Neon project by organization plus project name.
- [x] Existing key tags migrate without loss.
- [x] Identically named targets in different services or dimensions do not share assignments.
- [x] Removing a service deletes its assignments.
- [x] A temporarily missing target keeps its assignment and appears as unavailable; its previous spend is not reused as current-month spend.
- [x] A label-only target that is renamed is treated as a new target.
