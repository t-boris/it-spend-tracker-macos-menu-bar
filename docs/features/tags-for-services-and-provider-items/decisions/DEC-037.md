## Context

AC-005 keeps the assignment of a temporarily missing target and shows it as unavailable; a renamed label-only target becomes a new target, so its old assignment never returns. The specification does not say how a stale assignment is removed: a missing target has no page of its own on which to edit its tags.

## Alternatives

1. Prune assignments of targets missing for several months (contradicts AC-005)
2. Leave stale assignments unremovable until the service is deleted

## Decision

Nothing is pruned automatically. Every row of the Tags view, including a missing target, has an "Edit tags…" action that opens the same editor as the target's own page, so the user can remove a tag from a target that no longer exists. Removing the last tag deletes the assignment.

## Reason

Keeps AC-001 ("add and remove tags") true for every target and avoids both silent data loss (auto-pruning would contradict AC-005) and assignments that can never be removed.

## Consequences

Renamed label-only items leave a stale unavailable row until the user cleans it up. Marked proposed: an AI reading that fills a gap in I-5.
