## Context

The user asked to add GitHub as a spend source. DEC-012 fixed the built-in connector list; it requires provider research before a connector is built.

## Alternatives

1. Built-in GitHub connector using the enhanced billing platform REST API
2. Manual entry only

## Decision

GitHub is a built-in connector. It reads `GET /users/{username}/settings/billing/usage?year=…` (and, when an organization is given, `GET /organizations/{org}/settings/billing/usage?year=…`) with a personal access token, sums `netAmount` per day as spend, and breaks it down by product/SKU (line item) and by repository or organization (project). Fixed plans (GitHub Pro, Copilot individual plans, seats) are not reported by the API and are added as subscriptions inside the service (DEC-026). GitHub exposes no API listing a user's own tokens, so no key details are shown.

## Reason

The user wants GitHub costs tracked; the API returns billed amounts in USD for up to 24 months.

## Consequences

The token needs the "Plan" user permission (read) for fine-grained tokens, or a classic token; GitHub's docs are inconsistent about fine-grained support, so both are accepted and a rejection is reported clearly. Accounts without the enhanced billing platform get an error and can use manual entry.
