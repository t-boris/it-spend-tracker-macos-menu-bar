## Context

DEC-028 read the personal account and at most one manually entered organization. The user expects all organizations, each shown separately with everything inside.

## Decision

The GitHub connector lists the user's organizations (`GET /user/orgs`) and reads the billing usage of the personal account and of every organization the token may read (organization admin; token with "Administration" read). The service page adds a breakdown "By account / organization"; within it, costs are also broken down by repository (prefixed with the account) and by product/SKU. Organizations whose billing cannot be read are listed on the service page as "not readable" with the reason; they never fail the refresh. The optional organization field remains for organizations not returned by `/user/orgs`.

Notes are either warnings (something to fix, e.g. a missing token scope; orange) or information (a fact, e.g. GitHub's 403 "No access to billing usage data" for an organization without billing data; neutral), and the user can hide any note per service; hidden notes stay hidden across refreshes and can be shown again.

## Reason

The user wants every organization's costs visible separately.

## Consequences

The token must be a classic personal access token with the scopes `user`, `repo` and `read:org` (SRC-002); fine-grained tokens are single-owner and receive HTTP 404 for other organizations. The personal account and each organization are read independently; the refresh fails only if none can be read.

A third breakdown dimension (account / organization) is added (REQ-015).
