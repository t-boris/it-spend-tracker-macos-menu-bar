## Context

The specification used the AI only for onboarding (REQ-005, REQ-012). The user expects to talk to the AI about the collected data: why spend changed, what to cancel, which keys are unused.

## Decision

The window gets a "Chat" section. The user asks in plain language; the app sends to the same local CLI (Claude Code or Codex, DEC-004), with all tools disabled (DEC-011), one prompt containing the conversation so far and a compact JSON snapshot of the app's data: per service and month spend (with ≈ marks), subscriptions, breakdowns, keys (name, project, created/last used/expiry, requests, cost, tags) and warnings. Credential values, key secrets and hints are never included. The answer is shown as text; nothing in it is executed, and the AI cannot change data. The conversation is kept in memory for the session only. Answers are requested in the UI language (DEC-018).

## Reason

The user's goal is deciding what to keep or cancel; a question-and-answer view over the collected data serves that directly.

## Consequences

Verified 2026-10-01 with the real Claude Code CLI: asked why spend rose last month over a real snapshot, it answered in the UI language and named the main cost driver.

Each question re-sends the snapshot (≈ a few thousand tokens) through the user's CLI subscription. Snapshot size is capped (12 months, top breakdown rows).
