## Context

REQ-006 said that no spend data is sent to any service other than the provider being queried and that the onboarding AI receives only the service name, account identifier and connector metadata. Since then the app gained the spending chat (DEC-038) and invoice import from a PDF. Both send data to the same local AI CLI (Claude Code or Codex, DEC-004), which passes it on to its own provider under the user's subscription. The requirement text no longer matches what the app does, and the privacy boundary was written down only per feature.

## Alternatives

1. Keep the original wording and no chat or invoice import: rejected, the user asked for both (DEC-038).
2. Run the chat and invoice reading against a local model so no data leaves the Mac: rejected for v1, the user chose their existing CLI subscription (DEC-004).

## Decision

One rule for everything the local AI CLI receives. (1) Credentials never reach it: no API key, token, password or key hint appears in a prompt, a CLI argument, the CLI environment or any file the CLI can read (DEC-011). (2) Onboarding sends the service name, the account identifier, the user's note and connector metadata (DEC-011). (3) The spending chat sends the conversation and a compact snapshot of the collected spend data, only when the user asks a question (DEC-038). (4) Invoice import sends the text of the PDF the user chose, only after the user has agreed to it for that file in the sheet. (5) The CLI always runs from an empty temporary directory with all tools disabled except web search for a service without a built-in connector (DEC-022), and its output is never executed. No other service receives spend data from the app; the providers that are queried already hold their own data.

## Reason

The user decides what to keep or cancel by asking questions over the collected data and by adding invoices, so the assistant must see spend data and invoice text. Credentials give access to the providers and have no use for the assistant, so they stay out entirely. Writing the boundary as one rule keeps REQ-005, REQ-006 and REQ-018 consistent and testable.

## Consequences

The data sent in the chat and invoice import is processed by the provider behind the user's CLI (Anthropic or OpenAI) under that account's terms; the app cannot control that. Tests cover: no credential in any prompt, the empty working directory and minimal environment, the https-only links in AI text, and the consent step before an invoice is sent. REQ-006 is reworded to match, and REQ-005 and REQ-018 keep their own criteria.
