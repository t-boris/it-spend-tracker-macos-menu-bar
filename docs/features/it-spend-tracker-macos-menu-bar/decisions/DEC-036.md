## Context

Google's billing export attributes cost to projects, services and SKUs, never to API keys; Cloud Monitoring reports request counts per key and per API. The user wants a per-key figure even if approximate.

## Decision

For Google, the month's cost of each (project, Google service) pair from the billing export is split across the project's API keys in proportion to their requests to that service in the same month (Cloud Monitoring, grouped by key and service); keys with no requests get nothing, and cost of services no key called stays unattributed. The result is shown as the key's current-month cost marked "≈" on the key row, the key page and the Tags tab, with the share explained. It is an estimate: requests differ in size. Service and project totals are unchanged.

## Reason

The user asked for it, accepting an approximation.

## Consequences

Per-key cost for Google exists only for the current month and only once the billing export has data.
