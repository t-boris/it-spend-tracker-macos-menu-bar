## Context

The app is personal and single-user; the user prefers a Russian UI. The UI language was only inferred (SRC-001), not decided. AI onboarding explanations are produced by Claude/Codex CLI (DEC-003, DEC-004).

## Alternatives

1. English-only UI
2. Russian and English with in-app or system-based switching
3. Russian-only UI with all strings externalized for later localization

## Decision

v1 UI is in Russian only. All user-facing strings are kept in an Xcode String Catalog (no hard-coded text) so other languages can be added later. Provider names, key names and technical terms (API key, token) are shown as-is. The AI onboarding prompt asks the assistant to answer in Russian. Amounts use USD formatting with Russian locale conventions for dates and numbers.

## Reason

The sole user prefers a Russian UI; shipping two languages adds translation and testing cost with no v1 benefit, while externalized strings keep the option open cheaply.

## Consequences

No language switcher in v1. Acceptance checks must verify all panel, form, warning and onboarding texts appear in Russian. Adding English later needs only translations, not code changes. This is an AI-proposed resolution pending user confirmation.
