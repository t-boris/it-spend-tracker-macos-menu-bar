## Context

Cline (cline.bot) sells credits and the Cline Pass subscription. Its account API (`api.cline.bot`, undocumented, endpoints taken from the Cline CLI 3.0.65) reports usage, payments and balance, but accepts only a sign-in session: a WorkOS access token valid for 1 hour plus a refresh token. There are no API keys for account data. Usage paid with the user's own provider keys inside Cline is already covered by those providers' connectors.

## Alternatives

1. Sign in from the app (WorkOS device authorization), session in the Keychain, renewed before each refresh
2. Reuse the Cline CLI's session from `~/.cline` (reads another app's secrets outside the Keychain; renewing could sign the CLI out)
3. Manual entry only

## Decision

Option 1. "Sign in with Cline" opens the browser with a code to confirm; the session (`accessToken`, `refreshToken`, `expiresAt`, `userId`, `email`) is the service's Keychain credential. Connectors with a session implement `SessionConnector`: before each fetch the refresh engine asks for renewed credentials and saves them to the Keychain immediately (without resetting stored history), so a rotated token survives a fetch that fails afterwards. A rejected refresh token shows "sign in again" and keeps the data; signing in again with the same Cline account keeps the stored history, a different account is refused (it can be added as a separate service). An access token rejected before its stated expiry is marked expired so the next refresh renews it.

Mapping (user's choice "usage + Pass"):
- Spend: credits used per UTC day (`creditsUsed`, millionths of a dollar) for the personal account and the user's member usage in each organization, plus Cline Pass payments (`type = plan`, cents) on their payment day. `metadata.is_byok` is not a filter: such records were still debited.
- Credit top-ups (`type = credits`, completed) are imported as credit purchases marked with the provider's payment ID; they are informational (DEC-023) and replaced on every refresh, manual purchases are kept.
- The personal balance (`balance`, millionths of a dollar) becomes the service's balance snapshot on each refresh and is not entered by hand; if it cannot be read, the stored balance is dropped ("no data") with a warning note instead of being shown as current. Organization balances are shown as notes when readable.
- An organization whose usage is not readable (403/404) gets a warning note; any other error fails the refresh so stored figures are kept. Unreadable dates or missing amounts fail the refresh instead of counting as zero.
- Requests use `Authorization: Bearer workos:<token>`; usage pages via `limit=200&cursor=<nextToken>`, newest first.

## Consequences

The connector depends on an undocumented API and on Cline's WorkOS client ID; a change on Cline's side shows as a refresh error. Organization endpoints are implemented from the CLI's types but have not been tested against an organization account. Checked against a live account: the computed balance agreed with the reported balance, and monthly usage matched the provider's dashboard.
