## Context

DEC-008 shows purchased/consumed/remaining balance where the provider exposes it, else 'no data'. Research (SRC-002) shows that none of the v1 connectors exposes a remaining balance, so 'remaining' would always be 'no data'. The discussion had asked whether the user would enter the balance manually; that was unanswered.

## Alternatives

1. Manual balance snapshot plus an estimate
2. Keep 'no data'

## Decision

For any service the user may record a balance snapshot: the credit balance in USD as of a date. The app shows remaining balance as an estimate: snapshot + credit purchases recorded after the snapshot date − credit consumption reported by the provider API after the snapshot date. It is labelled as an estimate. Without a snapshot, remaining shows 'no data'. Purchased is the sum of recorded purchases; consumed is the provider-reported consumption (or 'no data'). None of these values count toward spend (DEC-008).

## Reason

The user chose to see when credits run out even though providers do not expose the balance.

## Consequences

The estimate drifts if purchases are not recorded; a new snapshot resets it.
