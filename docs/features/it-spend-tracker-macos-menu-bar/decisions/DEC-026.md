## Context

The user pays a fixed monthly amount to a provider for accounts or seats and expected to see it under that provider. The OpenAI Admin API returns only API usage; subscriptions, seats, invoices and payments have no API (SRC-002). Manual subscriptions were only possible as separate manual services.

## Alternatives

1. Fixed subscriptions inside any service, including API-connected ones
2. Keep subscriptions as separate manual services

## Decision

Every service, API-connected or manual, can have any number of fixed subscriptions (name, USD amount, monthly or yearly, start date, optional end date, price history as in DEC-014). A service's spend is its provider usage cost (API-connected) plus its subscription charges due in the period, plus recorded credit purchases for manual services only (DEC-023). The service page shows the split usage · subscriptions · total.

## Reason

The user wants all costs of a provider in one place; usage and subscriptions are distinct payments, so nothing is double counted.

## Consequences

Subscription data moves to its own records (no existing data needed migration). Invoices and payment history remain unavailable for providers without such an API.
