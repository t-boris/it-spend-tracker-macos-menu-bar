## Context

A user may have several Google billing accounts and needs to know whether one key or one per organization is required. Findings: the console lets a billing account export only into a project linked to that same billing account; a billing account may have at most 5 linked projects (quota), so projects could not be consolidated onto one account.

## Decision

One read-only service account (`<name>@<own-project>`) with one JSON key reads every billing export: BigQuery Job User on its own project and dataset READER on each export dataset. Each billing account exports its standard usage cost into a dataset in one of its own projects. The Google Cloud connector accepts several datasets (`project.dataset`, comma-separated), discovers all `gcp_billing_export_v1_*` tables in them, queries them together, and adds a breakdown by billing account; an optional billing account ID restricts it to one. An empty export shows "no data" with an explanation instead of an error. A prepared connection can be passed to the app once at launch (`-ImportConnectionFile <path>`): the app stores the credentials in the Keychain, creates the service and deletes the file.

## Reason

The user wants everything tracked with as few keys as possible and set up without manual entry.

## Consequences

Setup: each billing account exports into a dataset in one of its own projects, and the service account gets dataset READER on each export dataset. A billing account with no billed projects has nothing to export; if it is billed later, enable its export and grant the same service account dataset READER. Other billing accounts are added to the same key the same way. A detailed export is separate and is not read by the app.
