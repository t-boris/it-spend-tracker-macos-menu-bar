## Context

Billing data requires provider-specific integrations; v1 scope of supported providers was undefined.

## Alternatives

1. Fixed list of v1 connectors
2. Generic connector for any service

## Decision

v1 ships built-in connectors for OpenAI, Anthropic, Vercel, Neon, Fly.io and Google Cloud/Firebase (via Cloud Billing BigQuery export). Any other service is added as a manual subscription or manual credit purchase. Each connector declares which data it provides (spend, per-key details, balance, token usage); unsupported fields show 'no data'. API capabilities of each provider (admin keys, per-key data, history depth) are unverified assumptions to be confirmed by research before implementation; a provider found to lack a usable API moves to manual entry.

## Reason

Covers the providers named in the idea with deterministic, testable integrations; a generic connector is unreliable and unsafe.

## Consequences

A research task per provider is required; a new requirement lists v1 connectors and their data capabilities.
