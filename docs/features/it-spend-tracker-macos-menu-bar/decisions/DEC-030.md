## Context

The user wants to "learn more about a specific key, whatever is possible". REQ-003 showed only a key row (name, last used, expiry, current-month spend).

## Alternatives

1. A key page with everything the provider returns about the key, its tags, token usage by model and per-key cost history where available
2. Keep the key row only

## Decision

Each key opens its own page in the main window with: name, service, provider project/workspace, masked value, owner (name, e-mail, role or type) when reported, status, scopes/origin when reported, created, last used and expiry (with the 14-day warning), tags (editable), current-month cost and its share of the service's usage, cost by month where the provider reports per-key cost, and this month's token usage by model with request counts when reported. Unavailable facts show "unavailable". OpenAI per-key costs are requested for the full backfill range; when OpenAI rejects older ranges it names the earliest allowed time, and the connector retries from there, falling back to the current month.

## Reason

The user wants per-key insight; this uses only data the provider APIs already return (SRC-002), with no estimates.

## Consequences

Per-key monthly costs are stored per service and key, replaced for refreshed months, and deleted with the service. Anthropic, Vercel, GitHub and Google Cloud report no per-key cost, so their key pages show metadata and (Anthropic) token usage only.
