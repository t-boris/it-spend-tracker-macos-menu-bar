## Context

After connecting an API-billed service the user saw "This month: 0" and an empty history, although 12 months of usage cost had been loaded. DEC-020 defaulted OpenAI to "Prepaid credits", where only recorded purchases count as spend, and the app cannot know the account's billing mode. The user rejected having to declare it.

## Alternatives

1. Default every connector to "Pay after use", prepaid mode optional
2. Require choosing the mode when connecting
3. Always count usage; show credit purchases only as information; remove the mode

## Decision

The billing mode is removed. For API-connected services (built-in or approved AI-proposed connectors), the provider-reported usage cost is the service's spend in the main number, totals, history and warnings. Credit purchases recorded for such services are informational only (purchased total, balance) and are never added to spend. For manual services, which have no usage data, the subscription charges and recorded credit purchases remain their spend (DEC-014, DEC-008). The remaining balance estimate (DEC-021) is snapshot + later purchases − later usage cost reported by the provider.

## Reason

The user wants to see what each service actually costs immediately, without extra configuration.

## Consequences

DEC-020 is superseded; DEC-008's cash-basis rule now applies only to manual services. Totals may differ from card statements for prepaid API accounts (usage instead of top-ups). Stored data needs no migration; existing services simply stop using the mode.
