## Context

Spending data must be fetched from provider billing APIs; the refresh strategy determines data freshness, API load and error handling.

## Alternatives

1. Refresh when the panel is opened (with cache) plus a Refresh button
2. Manual refresh only via a Refresh button

## Decision

The app refreshes provider data automatically in the background every few hours and offers a Refresh button for on-demand updates.

## Reason

The user chose data that is already fresh when the panel is opened.

## Consequences

More API calls and a need to handle background failures gracefully (keep last known data, show error indicator); the panel displays cached data instantly.
