## Context

During implementation the user asked that the assistant be "very flexible" with new services: when the user says, for example, "I also use ExampleAI and pay this much", the assistant should check whether the provider offers an API key for spend or token usage and connect it. DEC-011 (advisory only, all tools disabled, output never executed) and DEC-012 (fixed connector list, "AI cannot add support for new providers dynamically") excluded this.

## Alternatives

1. AI-built declarative connector, reviewed and approved by the user
2. AI advises only; unknown services are manual entries (DEC-011/DEC-012 unchanged)
3. Advice in v1, AI-built connectors in v2

## Decision

For a service without a built-in connector the assistant researches the provider and returns either "no usable API" (the service is added by manual entry) or a **declarative connector definition** (JSON, never code): an HTTPS base URL, the authentication header scheme, the credential fields to ask for, and for each of spend, token usage and key list an HTTP GET path plus JSON paths to the values. The app validates the definition and shows it to the user in plain form (host, endpoints, which data it reads). Only after the user approves it is it saved. A generic engine then performs only GET requests to the definition's host over HTTPS, with the secret sent only in the declared header. Credentials are entered in native form fields and stored in the Keychain; they never reach the AI.

For this research call only, the CLI may use web search/fetch tools; file, shell, MCP and all other tools stay disabled, it runs from an empty temporary directory, and it receives only the service name, account identifier and the user's free-text note (e.g. the price paid). The AI's output is parsed as data and is never executed. Built-in connectors (REQ-011) are unchanged, and any data a definition cannot provide shows "no data".

## Reason

The user chose flexible support for new services with explicit approval, keeping secrets and code execution away from the AI.

## Consequences

DEC-011 is amended: web tools are allowed for new-service research, and AI output may become a stored connector definition after user approval. DEC-012 is amended: the connector list is extensible by approved definitions. The generic engine can only read JSON over HTTPS GET from one host; APIs needing other flows (POST queries, OAuth, signed requests) fall back to manual entry. REQ-005 and REQ-011 are updated and REQ-012 is added.
