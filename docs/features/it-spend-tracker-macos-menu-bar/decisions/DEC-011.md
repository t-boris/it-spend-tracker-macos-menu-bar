## Context

Agentic CLIs can read files and run tools; how credentials are kept away and how AI output becomes a connector was undefined.

## Alternatives

1. AI only gives instructions; connectors are built in per provider
2. AI generates API call config dynamically

## Decision

The CLI is invoked non-interactively in print mode with all tools disabled (no file, shell or network tools), from an empty temporary working directory, and receives only the service name, account identifier and connector metadata. Its output is displayed as guidance text only and is never executed. Credentials are entered exclusively in native app form fields defined by the built-in connector and are stored in the Keychain; they are never placed in prompts, CLI arguments, environment or files the CLI can access. Services without a built-in connector are offered manual entry.

## Reason

Removes the risk of the agent reading secrets or executing generated code, and keeps connectors deterministic and testable.

## Consequences

REQ-005 criteria are extended with sandboxing and native credential entry; AI cannot add support for new providers dynamically.
