## Context

The user asked for a Neon connector. DEC-012 routed Neon to manual entry because its API reports only usage, not money (SRC-002, re-checked 2026-09-30). Neon documents computing cost as usage × plan rate − allowance.

## Alternatives

1. Estimate cost from usage with built-in plan rates
2. Usage only, no dollars
3. Usage from the API plus spend entered manually as a subscription

## Decision

Neon becomes a built-in connector that reads the consumption history (v2, monthly, up to 12 months) for every organization the API key can see, per project: compute (CU-hours), storage (root, child, instant restore, snapshots; GB-months), network transfer (public, private; GB) and extra branches (branch-months), using Neon's documented conversions. The app shows these usage figures per month, in total and by project. No dollar amount is computed: the service's spend comes from subscriptions the user enters from the Neon invoice (DEC-026); without a subscription its usage cost shows "no data".

## Reason

The user chose usage from the API plus manual spend, avoiding estimates.

## Consequences

A generic "usage metrics" store and view is added (REQ-017) that other connectors can use later.
