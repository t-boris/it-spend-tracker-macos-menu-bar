## Statement

The app records prepaid credit purchases (date, USD amount, volume, service), entered manually or fetched via API where the provider allows it. For API-connected services purchases are informational (their usage cost is the spend, DEC-023); for manual services purchases count as spend in the month of purchase. For each service it shows purchased and remaining credit balance, and token usage per service and per key.

## Acceptance Criteria

- [x] User can create, edit and delete a credit purchase with date, USD amount, optional volume (credits or tokens) and service
- [x] For a manual service a credit purchase counts as spend in the month of purchase; for an API-connected service it is informational only
- [x] Purchased (sum of recorded purchases) is shown
- [x] The user can record a balance snapshot (USD, date); remaining is then shown as an estimate = snapshot + later purchases − later provider usage cost, otherwise "no data" (DEC-021, DEC-023)
- [x] Token usage for the current month is shown per service and per key as input, output and (when reported) cached tokens, broken down by model; "no data" when the provider does not expose it
- [x] Token usage is never added to any spend figure
