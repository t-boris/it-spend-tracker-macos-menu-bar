## Statement

When the user names a service with no built-in connector, the assistant checks whether the provider offers an API for spend, token usage or key details and, if so, proposes a declarative connector definition that the user reviews and approves; otherwise the service is added by manual entry.

## Acceptance Criteria

- [x] For an unknown service the user can ask the assistant to look for an API; the CLI may only use web search/fetch tools for this and receives only the service name, account identifier and the user's note
- [x] The assistant's explanation names the keys needed and links directly to where each is created
- [x] The assistant's answer is parsed as a JSON definition (never executed); invalid or non-HTTPS definitions are rejected with an explanation, and manual entry stays available
- [x] Before saving, the user sees the host, endpoints and data the definition reads, and must approve it
- [x] The engine performs only HTTPS GET requests to the definition's host and sends the secret only in the declared header; secrets are entered natively and stored in the Keychain
- [x] Spend, token usage and keys from an approved definition appear like built-in connector data; missing parts show "no data"
- [x] The service can be refreshed and removed like any other
