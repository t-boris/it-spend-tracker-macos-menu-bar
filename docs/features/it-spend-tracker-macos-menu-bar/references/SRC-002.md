## Summary

| Provider | Usable spend API | Basis | Per-key details | Tokens | Balance |
|---|---|---|---|---|---|
| OpenAI | yes | Admin key; `GET /v1/organization/costs` (daily, USD numbers, group_by project_id/line_item/api_key_id) | name, created, last used, expiry (per project keys); spend per key via costs group_by api_key_id | `/v1/organization/usage/completions` group_by api_key_id, model (input, cached, output) | not exposed |
| Anthropic | yes | Admin key (organizations only); `GET /v1/organizations/cost_report` (daily, amounts are cent strings) | name, created, expiry, status; no last used; no per-key cost | `/v1/organizations/usage_report/messages` group_by api_key_id, model | not exposed |
| Vercel | yes | Access token; `GET /v1/billing/charges` (FOCUS JSONL, daily, USD, BilledCost) | `/v6/user/tokens`: name, created, active at, expiry; no per-token spend | not exposed | not exposed (AI Gateway only, separate key) |
| Neon | **no** | Consumption API returns usage metrics only, no money | — | — | — |
| Fly.io | **no** | No documented billing API (GraphQL is undocumented) | — | — | — |
| Google Cloud / Firebase | yes | Service-account JSON key; BigQuery `jobs.query` on the Cloud Billing standard export table; net cost = cost + credits; non-USD billing currency converted with the export's own `currency_conversion_rate` | not provided in v1 | not exposed | not exposed |

## Content

Details (endpoints, auth headers, response shapes) were gathered from platform.openai.com / openai-openapi spec, platform.claude.com, vercel.com/docs, neon.com/docs, docs.fly.io, and docs.cloud.google.com on 2026-09-30. History depth is undocumented for OpenAI, Anthropic and Vercel (connectors request 12 months, DEC-015); the GCP export contains data only from the month before export was enabled.

## Verified in use (2026-09-30)

OpenAI rejects `GET /v1/organization/costs?group_by[]=api_key_id` for older ranges with HTTP 400
("group_by=api_key_id is not available for this time range. Try a start_time on or after <timestamp>").
The connector therefore fetches daily costs for the full backfill range without grouping and requests the per-key
breakdown for the current month only; if that is rejected too, per-key spend is shown as unavailable.

## GitHub (researched 2026-09-30)

Usable spend API: yes. `GET https://api.github.com/users/{username}/settings/billing/usage?year=&month=&day=` (orgs: `/organizations/{org}/settings/billing/usage`) returns `usageItems[]` with `date`, `product`, `sku`, `quantity`, `unitType`, `pricePerUnit`, `grossAmount`, `discountAmount`, `netAmount` (billed amount), `repositoryName` (and `organizationName` for orgs); up to 24 months. Headers: `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2026-03-10`. Token: fine-grained PAT with "Plan" user permission (read) per the REST reference; the tutorial says only classic PATs work (docs inconsistent). Fixed plans (GitHub Pro, Copilot plans, seats) are not documented as line items. No API lists a user's own tokens. Sources: docs.github.com/en/rest/billing/usage, docs.github.com/en/billing/tutorials/automate-usage-reporting.

## Anthropic Admin keys (re-checked 2026-09-30)

"The Admin API is unavailable for individual accounts. ... set up your organization in Console → Settings → Organization" (platform.claude.com/docs/en/manage-claude/admin-api). Admin keys are created at Claude Console → Settings → Admin keys (platform.claude.com/settings/admin-keys) by members with the admin role (owners and primary owners included); individual accounts have no such page. Claude Pro/Max subscriptions on claude.ai are separate and have no billing API.
Individual accounts show an auto-created personal organization with no "Admin keys" item, and a "Convert to team organization → Convert to team" action under Settings → Organization. Credits balance is shown in the console sidebar (not via API).

Verified in use (2026-09-30): Vercel `GET /v6/user/tokens` returns `pagination.next` as a string (docs show a number); the connector accepts both, and an unreadable token list no longer fails the spend refresh.
Verified in use (2026-09-30): for a team `GET /v1/billing/charges` returns HTTP 404 `{"error":{"code":"costs_not_found"}}` and `{"error":{"code":"not_found","message":"Plan not found."}}` via teamId/slug. The docs and changelog state no plan restriction; the cause is unknown. The connector reports spend as "no data" with an explanation (not zero), still loads tokens, and the plan can be added as a subscription; other 404s remain errors.
Follow-up (2026-09-30): a later refresh of the same team succeeded (daily usage rows, no plan fee line). The earlier 404 did not recur; cause unknown (possibly transient). The "no data + explanation" handling stays for when it happens. The token list could not be read in that refresh (keys shown as unavailable).

Diagnostic for a team: a month of FOCUS data returned only `ChargeCategory` Usage lines, **`BilledCost` 0 on every line**, and `EffectiveCost` carried the plan fee amortized per day plus the usage lines. Ranges before the team's first data return 404 `costs_not_found`. The connector therefore sums `EffectiveCost` (falling back to `BilledCost`), treats 404 `costs_not_found` per range as "no data" for that range, and starts coverage at the first month with data. The Pro fee is already included, so it must not be added as a subscription.
Months before a team's billing data exist show "no data" and do not affect totals.

GitHub, verified in use (2026-09-30): with the user's fine-grained token every `/organizations/{org}/settings/billing/usage` returned HTTP 404 although the token owner is an organization admin. With a classic token (scopes repo, read:org) the same calls return 200 with data (e.g. an Actions line item with a USD amount); responses advertise `X-Accepted-OAuth-Scopes: admin:org, repo`. The personal endpoint `/users/{login}/settings/billing/usage` requires the classic `user` scope (`X-Accepted-OAuth-Scopes: user`). Items are monthly (dated the 1st). Required token: classic with `user`, `repo`, `read:org`. Fine-grained tokens are single-owner and cannot read other organizations.

Google Cloud, verified in use (2026-09-30): the billing export form only offers projects linked to the billing account being exported; a billing account may have at most 5 linked projects ("Cloud billing quota exceeded" when linking a 6th). Standard export tables appear up to a day after enabling. A detailed export, if present, is separate from the standard export.
Google Cloud export, observed 2026-10-01: the standard export tables were created within ~18 hours and backfilled from the first day of the previous month; `bq ls` may show the dataset as empty while `SELECT` over `gcp_billing_export_v1_*` returns rows.
